# Proxmox VE Storage Overview
- VMs are composed by files
- Must use a datastore so nodes can read and write data

Storage in Proxmox VE is flexible you can:
- Have local or shared storage
- Create as many storage pools as your hardware allows
- Use any storage technology compatible with Debian
# Local Storage vs Shared Storage
| **Feature/Storage Type**   | **Local**                                                                     | **Shared**                                              |
| -------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------- |
| *Access*                   | Only accessible by the node that it is physically connected to<br>Faster IOPS | Accessible by multiple nodes<br>Allows cluster features |
| *Migration*                | Not feasible to migrate VMs between nodes                                     | Seamless migration with minimal downtime                |
| *Scalability & Redundancy* | Each node is isolated<br>No redundancy                                        | Enables expansion and high availability                 |
# File-level Storage vs Block-level Storage
| **Feature / Storage Type​** | **File-level​**                                                                                                           | **Block-level​**                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| *Data Access​*                | - Stores and manages files as a hierarchy.​<br>    <br>- The file system manages organization and retrieval of the data.​ | - Stores data as raw blocks.​<br>    <br>- The client OS manages its own file system and the raw blocks.​ |
| *Performance​*                | - It may be a bit slower because it stores and manages data.​<br>    <br>- Recommended for lower I/O speed needs.​        | - Higher performance because data is accessed in blocks.​<br>    <br>- High I/O.​                         |

(ZFS is the most widely-used storage system. It is block-level, local and shared)
# Zettabyte File System (ZFS)
- Most popular and powerful
- Common favorite among Debian and Proxmox admins
- Acts as block-level by storing VM disk images and container data as raw blocks
- Has it own volume manager
- Has snapshots, compression and data integrity
- Mostly used as local storage via HDDs/SSDs
- Max 16 exbibytes
# Content Tags
Content tags must be set for each storage device in your environment. These tags define which types of data can be stored
- **Images** - Virtual disk images
- **vztmpl** - Container templates
- **iso** - Image files
- **rootdir** - Containers root directory
- **backup** - VZDump backup files generated by Proxmox
- **snippets** - Script for automation and configuration
- **imports** - Identifies storage areas used to store OVF/OVA files
# Logical Volume Manager (LVM)
- Allows admins to create storage pools
- A storage pool is commonly referred to as a volume group
- You can create logical volumes inside a storage pool to store VM and LXC files
- Logical volumes can be resized, even when running
## Features
**Thin Provisioning**
- Creates a disk that only tasks up as much space as it truly needs
- Optimizes storage resources by overcommitting available capacity and then managing real storage dynamically
**Snapshots**
- Take a "picture" of a point-in-time state of the volume
**Flexible Volume Management**
- Resizes volumes while workloads are running
