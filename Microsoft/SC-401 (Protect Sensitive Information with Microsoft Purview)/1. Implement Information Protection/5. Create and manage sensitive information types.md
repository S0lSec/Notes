# Compare built-in vs custom SITs
| **Built in**                                                         | **Custom**                                                                      |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Include default patterns                                             | Detects unique org data                                                         |
| Can't be modified but can be copied and customised                   | Fully defined or modified from built-in types                                   |
| Named entity SITs detect names, physical addresses and medical terms | Exact data match SITs detect structured values stored in a DB of sensitive info |
| **Best for common regulated data**                                   | **Best for high accuracy and reducing false positives**                         |
# Create and manage custom sensitive information types
- **Primary pattern** - Keyword or regex pattern for detection
- **Additional evidence** - Supporting keywords to raise match accuracy
- **Character proximity** - Distance between the primary pattern and supporting evidence
- **Confidence level** - Match accuracy and strength of evidence
# Best practices for a keyword dictionary
- Ensure relevance
- Standardise sources
- Refine over time
# Define custom sensitive information types and exact data match
Exact Data Match (EDM) SITs identify structured data from a predefined database, reducing false positives and supporting large-scale detection.

Create EDM SITs using new or class experience. 
New supports up to 10 EDM schema per tenant, classic requires manual schema and SIT setup and mapping.
### New Experience
- Creates the schema & SIT in one step
- Automatically recommends confidence levels
- Improves performance with built-in controls
### Classic experience
 - Allows more than 10 EDM SITs
 - Supports multiple SITs per scheme
 - Allows custom schema naming
# Implement document fingerprinting
Document fingerprinting creates a SIT to identify documents by structure, not keywords. For example a hash of a file.
It improves accuracy by detecting standard forms across an organise.
### How it works
1. Upload a template
2. Set detection rules
3. Identify matches
4. Apply policies
### Limitations
- Password-protected file + image aren't supported
- File must meet a minimum size
- File no larger than 4MB
- Embedded a document aren't processed
