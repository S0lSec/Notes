# Azure Site Recovery
Replicates workloads from a primary site or region to a secondary site. If the primary site has an issue, Site Recovery can replicate protected VMs to anther VM region.

Manages the replication of Azure VMs between regions, or the replication of on-prem VMs to Azure and back again.

## Recovery Services Vault
Enables Site Recovery to complete disaster recovery replication. These vaults use storage accounts to store data backups, VM configuration settings and workloads.
## Prepare for Disaster Recovery
1. Add a Recovery Services vault
2. Organise target resources
3. Configure outbound network connectivity
4. Set up replication on existing VMs

# Failover & Failback using Azure Site Recovery
## What is failover & failback?
Failover is used to ensure your production environment continues running after a disaster/incident.

Failover occurs when a DR plan for your org is being executed. The existing production environment, protected by Site Recovery is replicated to a different region.

Failback is the reverse of failover. It is when a failover has been committed and now the production environment is in the secondary region. In failback Site Recovery will failover back to the source VMs.
## What is reprotection, and why is it important?
Reprotection enable Site Recovery to start replicating your new target environment back to the source environment where it started.
