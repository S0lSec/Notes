Hyper-V failover clusters are used to make VMs highly available.![[Pasted image 20260828105658.png]]
Hyper-V replica can have two instances of a single VM on two different Hyper-V hosts. You would have a main VM running and a offline copy of the main VM which is the replica.
# Requirements
- Supported version of Win Server with the Hyper-V role installed on both locations
- Sufficient storage on both
- Network connectivity between locations
- Firewall rules to allow replication
- Authentication certification or AD DS infrastructure requirements
# Configure and Implement Hyper-V Replica
1. Enable Hyper-V host to act as a replica server
2. Enable replication on each VM that needs to be replicated on the primary Hyper-V host
# Extended Replication
![[Pasted image 20260828110542.png]]
Enables you to replicate a running VM to two independent servers which could be in different geographical locations.

Allows more redundancy since you have a third server you can replicate to if the first two fail.
## Limits
- Replication frequency can be 5min or 15min only
- Replication frequency can't be lower than the initial replication
- You can't change the authentication type
## To create an extended replica in Hyper-V Manager
- Select the replica VM
- Select Replication > Extend Replication
- In the Extend replication for *VMName* wizard, select the following:
	- Select the replica server that will act as the extended replica server
	- Select whether to compress the data that's transmitted over the network
	- Select the frequency at which changes are sent to the extended replica server
	- Select the option to maintain only the latest recovery points or create additional hourly recover
	- points
	- Select an initial replication method and schedule
# Azure Site Recovery![[Pasted image 20260828110954.png]]
A BCDR solution that can replicate VMs and physical servers to Microsoft Azure or to a second site.
When an outage occurs at your primary site, workloads on a primary site can failover to secondary location and access apps from that site.

Once the primary site is running again you can failover back to the primary VM.

The secondary site can be:
- On-prem
- In a different geographical area
- In Azure
