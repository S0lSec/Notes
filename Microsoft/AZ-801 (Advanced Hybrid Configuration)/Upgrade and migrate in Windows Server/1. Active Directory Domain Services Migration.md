Migration to a new AD DS forest is typically driven by a need to restructure AD DS and is more complex than upgrading an existing AD DS forest.

Some common reasons to migrate to a new AD DS forest are:
- An acquisition or merger
- Divesture of a company or business unit
- Need to rename the AD forest or domain
- AD DS compromised by a security event
- Aging AD DS forest that requires rationalization due to build-up of legacy configuration alterations
# Steps to upgrade AD DS
1. Add new member servers running Windows Server 2025
2. Prepare the forests and domains
3. Promote member servers to domain controllers
4. Transfer FSMO roles from existing domain controllers
5. Demote all domain controllers running prior versions of Windows Server
6. Upgrade the domain and forest functional level
# Steps to migrate AD DS
Before migrating be sure to plan carefully:
- Select new names
- Plan organizational unit (OU) structure
- Plan Group Policies
- Identify objects to migrate
- Identify apps that will be migrated

Then proceed with:
1. Create the new AD DS forest by adding new domain controllers running Windows  Server 2025
2. Configure a forest trust
3. Disable SID filtering on the forest trust to use sIDHistory
4. Migrate passwords along with the user accounts
# AD Migration Tool
Can be used when consolidating domains within a forest or when migrating to a new AD DS forest.

It can perform the following:
- Migrate user accounts
- Migrate service accounts
- Migrate groups
- Migrate computer accounts
- Translate security for local profiles

ADMT installed on a member server with Desktop experience and uses migration accounts
