### The defender portal includes:
- **Microsoft Defender for Office 365** helps orgs secure their enterprise resources
- **Microsoft Defender for Endpoint** provides protections for devices
- **Microsoft Defender XDR** automatically analyses threat data across domains
- **Microsoft Defender for Cloud Apps** cross-SaaS and PaaS solution providing protection for cloud apps
- **Microsoft Defender for Identity** is a cloud based security solution using on-prem signals to protect your org
- **Microsoft Defender Vulnerability Management** provides an assessment of your security
- **Microsoft Defender for IoT** is used for protecting critical sectors within the org
- **Microsoft Sentinel** is used to investigate incidents
# Map Microsoft Defender XDR Unified RBAC permissions
All permissions listed within the Microsoft Defender XDR unified RBAC model align to existing permissions in the individual RBAC models.

Once you activate the unified RBAC model the permissions and assignments configured in the your imported roles replace the existing roles in the individual RBAC models.
# Manage Incidents
Microsoft Defender XDR provides a cross-domain threat correlation and purpose driven portal to investigate threats.
Incidents are based on related alerts when a malicious event or activity is seen on your network.
Individual alerts provide valuable clues about an on-going attack.

Microsoft Defender XDR automatically groups alerts into a incident to give analysts a comprehensive view of an attack.
# Manage Automated Investigations
Microsoft Defender for Endpoint includes automated investigation and remediation (AIR) capabilities that can help address threats more efficiently and effectively.

Entities can be added to the scope of the investigation automatically as it goes on.
## How the automated investigation starts
1. Alert is triggered
2. Security playbook goes into effect
3. Automated investigation can start, depending on the playbook
## Details of an automated investigation
During and after an automated investigation, you can view details about the investigation.

| Details         |                                                                                      |
| --------------- | ------------------------------------------------------------------------------------ |
| Alerts          | The alerts that started the investigation                                            |
| Devices         | The devices where the threat was seen                                                |
| Evidence        | The entities that were found to be malicious during an investigation                 |
| Entities        | Details about each analysed entity, including a determination for each entity type   |
| Log             | The chronological, detailed view of all the investigation actions taken on the alert |
| Pending actions | Any actions awaiting approval                                                        |
## How threats are remediated
After the investigation a verdict is generated for each piece of evidence investigated.
As verdicts are reach, automated investigations can result in one or more remediation actions.

Depending on the level of automation set for your organisation and other security settings, remediation actions can occur automatically or only upon approval by your SOC team.
## Automation Levels
- **Full automation** - Actions are taken automatically on artifacts determined to be malicious
- **Semi-automation** - Some remediation actions are taken automatically but others wait for approval
All remediation actions are tracked in the Action Centre
# Action Centre
The action centre contains pending and completed remediation actions from Defender for Endpoint and Office 365.
